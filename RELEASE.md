# 26.11.1

**Project:** Kira UI  
**Release week:** 2026-11-02 – 2026-11-08

## Highlights

- Unified navigation chrome now sends its measured top-toolbar height and combined rail/sidebar width to Ember as one shared native displacement-field geometry. The same measurements drive the transparent cutouts, preventing the native refraction field from drifting away from the content boundaries after layout changes.

- Transparent macOS windows now host compositor-backed Liquid Glass beneath their Metal content. The renderer emits a Metal-generated refraction field over true behind-window blur only where the substrate is transparent; opaque surfaces keep the original KiraUI renderer.

- Split navigation keeps the **entire unified toolbar** on one semantic AppKit titlebar material, including the area over the sidebar. Only the sidebar **below** the toolbar receives a darker, translucent, system-derived tint; the rail remains untinted. At the content/toolbar/sidebar junction, a single top-leading continuous corner is actually composited into the content background, with `paneCornerRadius` defaulting to the native window token. No rounded sidebar/card wrappers or extra corners are added, and the content and sidebar retain their original hit-target geometry. The desktop/wallpaper blur remains native; other hosts retain the portable material.
- Standalone macOS windows with navigation chrome now opt into Ember's native behind-window material. The rail and sidebar share the same AppKit `NSVisualEffectView` as the full-width toolbar, while their KiraUI content remains independently hit-testable. The native mode cuts both toolbar and leading panes through the Metal framebuffer; hosts such as MosaicDisplay that provide only a sidebar material retain KiraUI's portable toolbar glass. Headless and non-macOS rendering also keep the portable fallback.
- Added `.presentationPlacement(.Automatic/.Center/.Leading/.Trailing)` to real sheet presentations. The sheet card now aligns to the leading or trailing safe window margin after its actual width has been resolved (including custom sizing), or remains centered for automatic/center. The placement is presentation-only and does not alter the underlying page or popover geometry. Nested presenting-view coordinate anchoring remains a host integration gap.

- Added `.presentationSizing` with a native extensible sizing-strategy contract, built-in automatic/form/page/fitted strategies, custom proposed-size callbacks, and chainable per-axis fitted and sticky behavior. The actual sheet and popover card dimensions now use the presented root's measured content size or explicit proposals; sticky axes grow but do not shrink during the presentation, and explicit sheet detents continue to own vertical height. Platform-private form/page minimums and native macOS sheet window resizing still require host comparisons.

- Added `.presentationContentInteraction(.Automatic/.Resizes/.Scrolls)` to native resizable sheets. The sheet's scroll-input router now resolves vertical swipe ownership against each embedded ScrollView's measured offset and available scroll range: resizes-first expands or collapses a reachable detent, while scrolls-first keeps the swipe with content until its boundary. Rerendering preserves the active gesture owner, and changes update the existing detent selection Binding without double-scrolling content. Native UIKit velocity-sharing and continuous partial-detent physics are not yet implemented.

Added a reusable native KiraUI `BlockEditor` for structured documents, composing SwiftUI-style text fields, the multiline code editor, menus, checklists and stable view identities without introducing an embedded web editor or custom color theme. It supports ten block kinds, contextual conversion/insertion/move/delete controls, Return-to-insert for text blocks and explicit slash command recognition, with rendering and behavior tests.

Expanded explicit native interop safety boundaries in Kira UI.
Added SwiftUI font designs, extended search placements and the two-axis safe-area bar API for native application ports.
Reimplemented flexible-frame sizing and alignment so nested max-width frames follow SwiftUI's layout proposal rules.
Introduced native vertical-axis multiline `TextField` editing and one-to-eight-line composer sizing.
Fixed document toolbar placement in applications with a custom full-height sidebar beside their detail content.
Added the SwiftUI split-view column-width overloads so the sidebar, document safe area, window toolbar and under-sidebar detail transitions share one width.
Restored native sidebar navigation titles in the unified window toolbar, with automatic large-to-inline title behavior on compact scrollable pages.
Expanded the scrollable large-title handoff to desktop split-view sidebars, independently of the detail navigation title.
Added SwiftUI's scroll-indicator visibility modifier and optional axes targeting, with real rendering and hit-testing behavior.
Added SwiftUI-style grouped/column form styles and inherited scroll/row background modifiers for native Settings screens.
Added SwiftUI's nullable Color-valued `.tint` overloads and appearance-resolved adaptive tints so entire control trees follow an application's color scheme.

## Changed

- Added `.presentationBackgroundInteraction` with automatic, enabled, disabled and enabled-up-through-detent policies. The native Sheet's actual backdrop hit region becomes pass-through at allowed detents (including bound height changes) and its underlying page remains accessible to assistive technology while background input is enabled.
- Added `.presentationBackground` with concrete theme colors, RGBA, elevation styles, materials and custom background views with alignment. Native sheets, popovers and full-screen covers draw these surfaces behind their clipped content without treating them as layout; uniform popover fills continue into the arrow. Generic ShapeStyle composition and arbitrary-view arrow masks remain outstanding.
- Added both `.presentationCompactAdaptation` overloads with all five strategies. The native popover and sheet hosts switch between popover, sheet and full-screen cover based on compact horizontal/vertical preferences while retaining the same bound presentation state and described content. AppKit windows remain regular; the mobile size-class determination is viewport-based until a UIKit trait bridge is available.

- Added `.onScrollVisibilityChange(threshold:action:)` with post-layout, viewport-clipped visibility observations. Each visible row's actual measured area is intersected with its nearest scroll container (and other clipping ancestors); callers receive initial and threshold-crossing Boolean events only when visibility changes. Nested scroll views and non-intercepting overlays are supported without changing hit testing or intrinsic layout. This observes geometric visibility, not GPU occlusion by opaque siblings.

- Added `.onGeometryChange` and `.onGeometryChangeNew` with generic transformed-value observations, old/new and new-only callback variants, and actual final placed size/window-frame data. Unlike a GeometryReader, the modifier does not expand or alter the view's intrinsic dimensions; its observer runs after stack layout, pixel snapping and scroll offsets. Changes in irrelevant geometry fields do not retrigger actions. Kira's `transform:` and separate new-only method replace Swift's metatype and closure-arity overload syntax; named coordinate spaces remain future work.

- Added `.onScrollGeometryChange` with generic transformed-value observations and actual old/new callbacks. Each observer retains a distinct comparison value for each receiving ScrollView, and unrelated geometry changes do not trigger a callback when the selected projection is unchanged. Actual offset/viewport measurements feed the same ScrollGeometry as phase-change handlers. Kira infers the generic type from `transform:` and `action:` rather than Swift's explicit `for: T.Type, of:` metatype syntax.

- Added `.onScrollPhaseChange` with both public callback signatures, all five ScrollPhase cases, and an optional context containing real measured scroll content size, container size, visible rectangle, offset and velocity. The native drag/wheel integrator distinguishes tracking before movement, interacting during active drag, inertial deceleration and programmatic animation; each scroll view notifies only on actual phase transitions. Current scroll geometry is vertical-only and platform velocity curves still need host comparisons.

- Added `.scrollEdgeEffectStyle(_:for:)` and `.scrollEdgeEffectHidden(_:for:)` with independent per-edge preferences. The native top toolbar/scroll intersection now draws either its existing hard glass and hairline or a soft, progressively faded blur using actual backdrop-glass bands; hidden suppresses the painted edge while retaining scrolling, indicators, and large-title behavior. Nullable styles restore automatic treatment. Bottom and horizontal pinned bars are not yet native scroll-edge receivers.

- Added both `.defaultScrollAnchor` overloads with independent `.InitialOffset`, `.SizeChanges` and `.Alignment` roles. The first layout measurement selects the real scroll offset; subsequent content or viewport changes preserve the chosen fractional anchor without resetting a user's scroll on unchanged frames. Content shorter than the viewport is actually aligned within it, without synthesizing overscroll. Optional nil restores the default for a role. The current native ScrollView is vertical-only; horizontal anchor behavior remains pending.

- Added `.presentationDetents` and `.presentationDragIndicator` to native sheet presentations. Medium, large, fractional and absolute detents change the actual modal card height; callers can bind the selected detent or use retained per-sheet state. An automatic/visible/hidden indicator draws a real gesture surface, and dragging its handle selects among permitted heights. Custom protocol detents and UIKit's exact detent animation/drag-to-dismiss semantics are still pending.

- Fixed the `Set<PresentationDetent>` overloads to enumerate the set through its actual `elements()` API; the ARM64 KiraUI framework now compiles with the current Foundation Set implementation.

- Added `.pointerVisibility(_:)` with automatic/visible/hidden cursor preferences in the actual Ember pointer backend. Independent transformed hover regions choose the innermost preference, including an inner automatic reset; entering, exiting or moving a view beneath a stationary pointer updates cursor visibility without intercepting its clicks, scrolls or hover callbacks.

- Added `.interactiveDismissDisabled(_:)` and `.presentationCornerRadius(_:)` for real Sheet presentation. The sheet host reads both preferences from its child once, disables the modal-scrim dismissal action when requested while leaving programmatic Binding dismissal possible, and applies the selected optional radius to the native card background and clipping; nil restores the style's default corner. Non-sheet presentations and native drag-down detents require additional host work.

- Added `.help(_:)` for String and Text explanations using real non-intercepting hover regions and a delayed, window-edge-constrained floating tooltip. The help tag is a transient overlay rather than inline content or a click-triggered popover, leaves the control's press/focus behavior unchanged, and also publishes its explanation as an accessibility hint. LocalizedStringResource and TabContent-specific overloads remain pending native Kira localization support.

- Added `.underline` and `.strikethrough` with five line patterns (solid, dot, dash, dash-dot, dash-dot-dot), optional literal ink and theme-semantic colors, and explicit on/off overrides. Decorations render as rotated, clipped stroke segments along each shaped text line in KCoreAnimation, including wrapped and truncated lines; they do not change text advance or the accessible source. SwiftUI's Text-returning attributed-run variants still require an attributed-text model.

- Added `.navigationLinkIndicatorVisibility(_:)` with inherited automatic, visible and hidden policies. It actually inserts or removes disclosure chevrons in grouped List links, sidebar navigation rows and standalone links without removing their navigation actions, accessibility labels or full-row click targets. Automatic restores the platform-style default for each presentation.

- Added `.focusEffectDisabled(_:)` as a real inherited visual focus/hover effect policy. Focusable views now draw an accent-colored focus border at their measured focus region, which the modifier can suppress without disabling focus, keyboard activation, or accessibility state. Parent policy wins over conflicting descendant settings, as documented by SwiftUI.

- Added focus-scoped `.onMoveCommand`, `.onDeleteCommand`, `.onExitCommand` and `.onPlayPauseCommand` handlers with optional-action and direct-action overloads. Keyboard commands bind to focused descendants or outer `.focusable` wrappers independently of modifier order, and route through the actual input dispatcher. Editing fields retain normal arrow/Delete behavior, menus retain Escape priority, and unfocused views never receive these commands. Native media-key mapping is still host-dependent; Space supports the keyboard play/pause equivalent.

- Added `.focusable(_:)` and `.focusable(_:interactions:)` with automatic, edit and activate modes. Focusable regions are hit-tested independently of click targets, editing views can focus on pointer down, and Tab/Shift-Tab traverse registered focusable views in description order. Activation-capable focused buttons answer to Space using their existing action, without double-firing on pointer press. Host-wide all-controls keyboard-navigation preferences remain to be connected.

- Added `.accessibilityActivationPoint` with concrete window-point and normalized UnitPoint overloads, including `isEnabled`. The accessibility tree resolves unit points against each element's actual laid-out bounds and defaults to the frame center; combined elements inherit a descendant's point unless overridden. This is accessible through the retained screen accessibility snapshot without changing hit targets or visual layout.

- Completed the existing `.scenePadding` modifier family with per-edge placement and the typed `.minimum` scene-padding overload. All four edges use the column's measured scene margin rather than constant generic padding; omitted edges reserve no space, and Section grouping survives either overload. Apple's `.navigationBar` value is watchOS-only and intentionally not exposed on KiraUI's current desktop/mobile hosts.

- Added `.redacted(reason:)` and `.unredacted()` with the full additive `RedactionReasons` set (placeholder, privacy, invalidated) and inherited subtree reset. Text keeps its original intrinsic and wrapped measurements while the compositor draws rounded placeholder bars instead of source glyphs; bitmap/texture images become actual placeholder fills and vector icons use a muted silhouette. Masked text and images no longer expose their content in the accessibility label.

- Added `.lineHeight(_:)` with variable, tight, normal, loose, exact, leading, multiple, and nil-reset choices. The actual baseline pitch is inherited by text, changes measured intrinsic and wrapped line heights, and is used during glyph-line placement separately from the font's ink bounds; explicit `lineSpacing` remains additive between lines. The named optical presets are approximations pending native TextKit comparisons.

- Unified rail-enabled macOS navigation chrome under one translucent sidebar-material recipe. The window now composites an edgeless toolbar band and a non-overlapping leading rail/sidebar region with identical blur and tint; native hosts keep their behind-window backdrop beneath the leading region, while standalone windows sample the in-window backdrop. The same treatment survives borderless presentation, without duplicate solid fills or Liquid Glass lenses around rail icons.

- Added `.fontWidth(_:)` with compressed, condensed, standard, expanded, relative and optional-nil reset variants. Font width is sent into KCoreAnimation's native variable-font `wdth` axis for both glyph outlines and measured advances, including the instance/atlas cache keys so width changes cannot reuse stale glyphs; fonts without a width axis keep their normal design rather than being distorted by a view transform.

- Added `.buttonRepeatBehavior(_:)` with automatic, enabled and disabled cases. Explicit enabled repeats a held real Button press after a short delay, accelerating its cadence while held over the control; a release after repeats does not double-trigger the normal click. Keyboard shortcuts honor repeated key-down events unless repetition is explicitly disabled, and disabled/menu controls never start a press-repeat timer.

- Added `.allowsTightening(_:)` using width-aware native text layout. A line-limited paragraph that nearly fits reduces inter-glyph-cluster spacing by at most four percent of the font size, with the same chosen spacing used for line breaking and actual glyph rasterization before falling back to font scaling or truncation. Explicit false restores normal spacing without changing source or accessibility text.

- Added `.tracking(_:)` and `.kerning(_:)` through native glyph-cluster spacing in KCoreAnimation. Tracking includes a trailing advance, kerning only adds space between clusters, and tracking takes precedence when both are present. Text intrinsic width, wrapping, truncation and actual rasterized glyph positions consume the same values, while inherited theme tracking applies where a font has not overridden it.

- Added a first-party `NavigationRail` and `NavigationRailItem` for the named rail slot of `NavigationSplitView`, with centered icon hit regions and an independent bottom action. The window owns the shared translucent rail, sidebar and toolbar background, including a native behind-window backdrop where the host provides one. Rail-enabled desktop windows center compact document titles in the toolbar and smoothly collapse scrolling large titles based on the actual scroll offset. `.navigationTitleUsesContentHeader()` lets editable document headings drive that same collapse without inserting a duplicate heading. Existing split views without a rail preserve their earlier toolbar and leading-title geometry.

- Added `.textScale(_:isEnabled:)` with SwiftUI's `.Default` and `.Secondary` semantic text scales. Secondary text is actually measured and drawn smaller relative to the active theme's body/subheadline typography without changing its color or content, and works with inherited Dynamic Type and explicit fonts. A disabled override retains its ancestor's scale.

- Added `.baselineOffset(_:)` as an inherited Text offset that expands the measured glyph box up or down and moves the real glyph baseline inside it, including wrapped runs and rotated text. Layout reserves the displacement before sibling placement; the source text and accessibility label remain unchanged.

- Added `.minimumScaleFactor(_:)` as a real line-limited Text resizing policy. The native font engine searches for the largest size that fits the complete source within the available line count, then both layout and compositor use that measured size before falling back to ellipsis. Works with custom font sizes, the inherited Dynamic Type selection and Unicode text without replacing the source accessibility label.

- Added `.dynamicTypeSize(_:)` with all twelve public size categories and native size-range constraints, including endpoint exclusion, partial ranges and intersection semantics. The effective category is inherited through the modifier environment and scales real Text glyph measurements and intrinsic layout through KiraUI's existing typography engine. Theme proportions and control-size scaling remain independent. Kira's native `DynamicTypeSizeRange` stands in for Swift's generic `RangeExpression` syntax until Kira supports enum-bounded ranges directly.

- Fixed `TextEditor`/vertical `TextField` text appearing far below its caret when `.lineLimit(min:max:)` reserves multiple lines. The viewport alone reserves the minimum height; the painted text run now retains its natural glyph height and stays top-aligned, with a regression for a fourteen-line document editor.

- Added `.navigationSubtitle(_:)` with String and Text overloads. Subtitles travel with page title preferences through navigation stacks, split columns, covered-page transitions and the window toolbar. The toolbar measures a real two-line native title group (normal title plus secondary, smaller subtitle) with one stable identity instead of inserting an unrelated text view into page content.

- Plain-list Sections now lower their child content through the same per-row adapter as loose rows, so each Section row independently consumes its hover effect and insets while the section's header and footer remain outside those row targets.

- Plain List now lowers its loose rows through a row-aware layout container instead of applying row insets after the entire scroll viewport is described. This enables the same full-cell `.listRowHoverEffect` and `.listRowHoverEffectDisabled` behavior for plain rows, including List-wide defaults, while continuing to preserve Section identity and row inset measurement.

- Added `.listRowHoverEffect(_:)` and `.listRowHoverEffectDisabled(_:)` as row-scoped list preferences. Grouped and sidebar lists consume the effect at the full measured cell boundary, not at an inset text label; explicit nil restores the list style, and disabling a row's visual effect does not disable its click or other hover listeners.

- Added `.defaultHoverEffect(_:)` for inherited built-in hover defaults; automatic hover effects resolve that policy at presentation time, while explicit highlight/lift modes retain precedence. A `nil` default leaves the inherited default unchanged. Hover-effect disabling now uses the parent's policy even when a descendant explicitly requests the opposite, matching SwiftUI's documented environment precedence.

- Added `.hoverEffect` with built-in automatic/highlight/lift behavior and `.hoverEffectDisabled(_:)`. Effects use the existing independent hover-region input channel, render a real theme-colored highlight or centered scale lift, and react through retained-layer reconciliation while leaving child press and accessibility behavior intact. Disabling effects is inherited and does not disable `.onHover` observations.

- Added `.onModifierKeysChanged(mask:initial:action:)` and `.modifierKeyAlternate(required:alternate:)`. Real Ember keyboard and pointer modifier state is published ahead of rebuilds, observations compare the requested mask by stable view identity, and alternate views swap their actual subtree on key transitions without intercepting mouse presses or stealing text-field focus.

- Added `.truncationMode(_:)` with head, middle, and tail modes to the actual shared text-layout engine. KCoreAnimation's Unicode-aware line breaking and measured ellipsis selection now agree between intrinsic sizing and text rasterization, including single unbreakable runs and line-limited multiline text, without changing the accessibility label's full source string.

- Added `.scrollDismissesKeyboard(_:)` with automatic, immediate, interactive and never cases. The scroll input dispatcher now releases active text focus at gesture start or after actual drag motion, depending on the policy recorded on the hit-tested viewport. Automatic distinguishes List/Form from standalone ScrollView; disabled scroll surfaces never dismiss the keyboard. Interactive mode currently drops focus on movement, pending host keyboard-frame animation support.

- Added `.listSectionSeparator(_:edges:)` and `.listSectionSeparatorTint(_:edges:)` with top/bottom visibility, theme-resolved colors, and `Automatic`/nil restoring the style's defaults. Plain List sections draw the actual upper/lower boundary hairlines around the section's rows, header and footer; unsupported list presentations do not invent separators outside their styles.

- Added `.onContinuousHover(coordinateSpace:perform:)` with `.Active(Point)` and `.Ended` phases, local/global pointer coordinates, and independent nested hit regions. Position updates come from transform-inverted presentation hit tests; stationary pointers do not spam callbacks, but views moving beneath them update after reconciliation.

Added `.labelsVisibility(_:)` through the existing inherited control-label visibility model, with focused override tests.

- Added `.allowsHitTesting(_:)` and `.compositingGroup()` backed by KCoreAnimation retained-tree primitives. Hit-testing exclusion prunes an entire subtree from pointer hit tests without altering its layout, drawing or accessibility; compositing groups isolate their subtree in an offscreen render target before blending.
